> **Примітка щодо автентичності.** Розділ A — **справжні запити** студента до AI (стислі цитати з
> історії роботи над проєктом). Розділ B — **шаблони промптів**, що відповідають виконаним крокам
> завдання; вони сформульовані так, щоб їх можна було запустити повторно й отримати подібний результат,
> але це не дослівний журнал. Якщо ви користувались іншими промптами чи іншими AI-інструментами
> (наприклад, ChatGPT) — додайте їх сюди: викладач може запитати про реальний процес.

## B. Промпти-шаблони за кроками завдання «AI для розробників»

### B1. Code review (частина 1)

**Промпт:**
```text
Ти — senior Django-розробник, який проводить code review. Нижче код view (<вставити код>) з контексту:
інтернет-магазин книг, Django 6, PostgreSQL, Stripe Checkout, транзакції з select_for_update.
Переглянь за критеріями: коректність, обробка помилок і компенсація побічних ефектів, безпека,
конкурентність, продуктивність, читабельність/тестованість.
Для кожної знахідки: серйозність (висока/середня/низька), чому це проблема, як відтворити,
запропонований фікс. НЕ пропонуй змін заради змін; якщо щось зроблено правильно — скажи про це.
```
**Результат:** таблиці знахідок у `AI_REVIEW.md` (C1–C6, W1–W6, B1–B6).
**Як перевірено:** кожну знахідку відтворено тестом на оригінальному коді (`16 failed, 2 passed`), після фіксу — `18 passed`.

### B2. Критична оцінка рекомендацій

**Промпт:**
```text
Для кожної твоєї рекомендації наведи контраргумент: у якому випадку вона шкідлива або зайва саме
для цього проєкту (зовнішній платіж, блокування рядків, відсутність черги завдань)?
Познач кожну: застосувати / відхилити / відкласти — і поясни.
```
**Результат:** відхилено C4 (одна транзакція навколо виклику Stripe), W4, W5, B6; відкладено C5, C6, W6, B4, B5.

### B3. Тести-відтворювачі

**Промпт:**
```text
Для кожної прийнятої знахідки напиши pytest-тест (pytest-django, factory-boy), який ПАДАЄ на поточному коді і
проходить після виправлення. Мокай лише зовнішні сервіси (Stripe). У кожному тесті — коментар
"# Generated with AI, reviewed and modified".
```
**Результат:** `tests/unit/test_review_regressions.py` (18 тестів).

### B4. Генерація тестів для моделей (частина 2)

**Промпт:**
```text
Згенеруй pytest-тести для моделей Category, Book, Order/OrderItem (код моделей: <вставити>).
Покрий: __str__, властивості, валідацію через full_clean (межі значень, max_length, unique), обмеження БД
(IntegrityError), on_delete (CASCADE/SET_NULL), Meta.ordering, related_name, точність Decimal,
кількість SQL-запитів (django_assert_num_queries), переклади verbose_name (uk/en).
Використай factory-boy. Тести прості, без умовної логіки всередині. Кожен — з коментарем
"# Generated with AI, reviewed and modified".
```
**Результат:** `tests/ai_generated/test_ai_models.py` (55 тестів); покриття моделей 100%.
**Ревʼю результату:** виправлено тести з гілками `if/else`; знайдено відсутню валідацію `Book.price`;
мутаційна перевірка 14/14.

### B5. Мутаційна перевірка тестів

**Промпт:**
```text
Запропонуй 10–15 «мутацій» коду моделей (зміна оператора, порядку, on_delete, прибрана валідація),
які мають зламати хоча б один тест. Напиши скрипт, що застосовує кожну мутацію, запускає тести і
відновлює файл.
```
**Результат:** 14 з 14 мутацій виявлено (результат — у `AI_REVIEW.md`).

### B6. Docstrings (частина 3)

**Промпт:**
```text
Проаналізуй AST файлів views і знайди класи/функції/методи без docstring. Для кожного напиши
docstring українською у форматі Google style (Args / Returns / Raises) з урахуванням реальної
поведінки: коди відповіді, побічні ефекти, обмеження доступу. Не вигадуй поведінки, якої немає в коді.
```
**Результат:** 22 docstring (всі 52 об'єкти задокументовано) + тест-сторож `tests/unit/test_docstrings.py`.
**Ревʼю результату:** переписано нечіткий текст для `CheckoutView.dispatch`; тест-сторож знайшов ще два
view з недостатніми docstring.

### B7. README та секція AI Usage

**Промпт:**
```text
Оновлення README: актуальний огляд проєкту (функціонал, стек, структура, запуск, тести), нові розділи
за останніми змінами та секція "AI Usage": що робив AI, які промпти, як перевірялись результати,
обмеження. Не описуй те, чого немає в коді; числа бери зі звітів покриття.
```
**Результат:** оновлений `README.md`; числа (кількість тестів, покриття) звірено зі звітами в `reports/`.

## C. Принципи роботи з AI в цьому проєкті

1. **Результат AI — гіпотеза, а не істина**: кожне твердження перевіряється тестом або запуском.
2. **Тести спершу падають**: тест-відтворювач пишеться до виправлення.
3. **Рекомендації можна й потрібно відхиляти** — з поясненням у `AI_REVIEW.md`.
4. **Зелені тести ≠ хороші тести** — перевіряємо мутаціями.
5. **Числа не вигадуються** — беруться зі звітів (`reports/`).
